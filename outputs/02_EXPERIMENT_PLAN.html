0 · Projected Abstract  PROJECTED — not results

Mixture-of-experts language models are aligned to refuse harmful requests, but recent work shows their refusal behavior concentrates in a few safety-critical experts, so disabling a small set of experts removes the safety guardrail. Existing defenses either restore refusal after an attack or require the original safety-aligned routing weights, which a deployed model does not have. We present SafeSpread, a method that spreads refusal behavior across many experts so that no small ablatable subset carries it. We first locate the safety-critical experts from routing statistics, then run a light LoRA fine-tune with a routing regularizer and an anti-concentration term that push refusal-relevant routing mass onto many experts, using only the deployed model. On standard harmful and jailbreak sets, SafeSpread lowers the worst-case refusal drop under expert ablation from [X%] to [X%], and keeps it below [X%] even when the attacker re-optimizes the ablation against the hardened model. It costs [X%] capability loss and adds no measurable over-refusal. These results give a deployable way to remove the expert-ablation vulnerability of aligned mixture-of-experts models.

2 · Systems — method + must-beat baselines

Method: SafeSpread

  • Locate safety-critical experts via SAFEx stability-based selection (SES).
  • Redistribute with a LoRA fine-tune: routing regularizer spreading refusal-relevant routing mass across many experts + anti-concentration entropy term on the critical set.
  • Regularize the router so it does not re-concentrate refusal after fine-tuning.
  • Attack-evaluate: worst-case k-expert ablation (static + adaptive) and input-only routing jailbreak.

4 · Run Order  smoke → baseline → main → ablation → polish

  1. Smoke (W1, cheap/deterministic first): OLMoE-1B-7B, 50 harmful + 50 benign prompts — verify SES localization, the ablation-attack harness, and the Llama-Guard judge run end-to-end and produce a refusal number.
  2. Baseline / audit: reproduce the SAFEx concentration curve on the undefended OLMoE (C1); run SAFEx-repair and SafeMoE baselines.
  3. Main: SafeSpread fine-tune + re-measure the worst-case ablation curve (C2).
  4. Adaptive: attacker re-optimizes ablation on the hardened model + input-only jailbreak (C3).
  5. Ablations: A1–A5, one variable each.
  6. Polish: transfer to Qwen3-30B-A3B; 3-seed repeats; capability + over-refusal tables.
