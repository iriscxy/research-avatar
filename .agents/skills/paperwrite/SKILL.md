The internal `paperstudio` skill owns only browser/API implementation and regression behavior; do not duplicate its state-machine instructions here.

## Workflow — the steps in order (Step 0–10)

The researcher invokes `$paperwrite` **once**; it runs Step 0–10 in this order and **calls the review
sub-skills itself** (theorization / related-work / gap-check / logic-check) and `figureppt` — she does
not call them by hand. Each step's detail lives in the section named in the arrow.

- **Step 0 — Venue contract, template, reference, approved embedded contract.** Read the venue already confirmed in approved `03` → verify its current official template/rules → reuse the confirmed researcher-owned structural reference → seed `budget.json` from its measured section shares → read the `experiment-plan-contract` JSON embedded in `reports/03_EXPERIMENT_PLAN.html` and require `approval_status=approved`. A missing, invalid, or pending contract routes back to `$expplan`; do not draft. (→ *§Step 0*)
- **Step 1 — Theorization.** `$papertheorization` decides the ONE formal spine and **mechanically verifies** it before any prose is written. (→ *§Review sub-skills · 1*)
- **Step 2 — Outline & confirm (key info + Method + artifact ledger) — a GATE before any prose.** **Seed the outline from `03`'s already-approved §0(b) projected paper skeleton and embedded contract** (the researcher approved both at `$expplan`, so do NOT re-invent the framing or evidence layout), write it to **`paper/outline.txt`** (plain text, bulleted) so the researcher can edit it directly, and **STOP for her to confirm or edit it BEFORE writing**: (a) the **key information** — working title · the 2–3 core claims / contributions · a one-paragraph story arc; (b) the **Method skeleton** — named modules and section/subsection plan; (c) the **complete artifact ledger** — every `F*`/`T*`, unique future LaTeX label, supported claim, required result dimensions, and approved body/appendix placement. Print the ledger diff against the embedded contract; any merge, deletion, relabel, or placement change is a plan revision and must return to `$expplan`, not merely be approved as a paper outline edit. **Read the (possibly edited) `paper/outline.txt` back** and write full prose only after she approves.
- **Step 3 — Working abstract + Paper Studio.** Establish a provisional abstract as the shared claim contract, then **automatically start Paper Studio and open its local browser page**; this is mandatory after Step 2 approval, not an optional response to a separate request. Give every section its own persistent GPT conversation; pair each paragraph with the corresponding reference-paper paragraph, expose the Step 2 working title through an editable title field plus Title GPT Prompt, accept edits transactionally into LaTeX, and compile the PDF after each confirmation. The final abstract is still rewritten in Step 6 after the body stabilizes. (→ *§Step 3*)
- **Step 4 — Method + Experiments.** **Only after the Step 2 outline is confirmed**, write these first (habit); tables come from `results/`; figures = data plots via `paper/fig/make_figs.py` **plus the model figure via `figureppt`** (gpt draft → `buildshapes`, every element editable, page-wide `figure*`). (→ *§Discipline · Figures*)
- **Step 5 — Related Work.** `$paperrelatedwork` — broad search, **verify every arXiv id**, ≤3 self-cites. (→ *§Review sub-skills · 2*)
- **Step 6 — Intro + Abstract.** Gap-first Intro; Abstract written **last**. (→ *§Personalization*)
- **Step 7 — Compile.** `latexmk`; extract and fix real build errors. (→ *§Scaffold & compile*)
- **Step 8 — Deterministic gates.** First run
  `python3 .agents/skills/paperwrite/scripts/plan_conformance.py`; it must pass
  before layout tuning and again before the whole-paper gate. Then run
  `python3 tools/paper_checks.py all` for budget / style / scholarship /
  consistency / length / formal / format / floats. A green layout board never overrides a red plan-conformance
  board. (→ *§Deterministic gates*)
- **Step 9 — Gap-check + Logic-check.** `$papergapcheck` (every claim → a `results/` file, never fabricate) then `$paperlogiccheck` (a fresh sub-agent reads the compiled PDF as a hostile reviewer). (→ *§Review sub-skills · 3–4*)
- **Step 10 — Fix → recompile → re-check**, presenting each section at the **GATE** for the researcher (human is the judge; never self-declare "done"). (→ *§GATE*)

The sections below are the per-step reference material, not a second workflow.

## Step 0 — Target venue, template, and a reference paper (fix FIRST, before writing)

1. **Inherit the confirmed target conference from approved `03`.** `reports/03_EXPERIMENT_PLAN.html` must contain the exact venue/track/cycle and its confirmation record from `$expplan`; treat that as authoritative. If an invocation argument explicitly requests a different venue, explain that this changes an approved plan and return to `$expplan`'s venue gate before writing. If `03` is missing the confirmed venue, stop and route back to `$expplan`; do not select or guess a venue here. Re-verify current official rules because templates and limits may have changed, but do not silently change the confirmed venue.
2. **Use that venue's official template.** Fetch the venue's current LaTeX style (e.g. `acl.sty` + `\documentclass` for *ACL Rolling Review*, `neurips_2026.sty`, `iclr2026_conference.sty`) and scaffold `paper/` from it — do NOT hand-roll a generic `article`. Match the real class, margins, font, and section format.
3. **Respect the length / word limits.** Enforce the venue's page/word budget (e.g. ACL 8 pages + unlimited refs; NeurIPS 9 pages; ICLR 9–10). Track current length as sections accrete and flag when a section pushes over budget; do not silently overflow.
4. **Reuse the researcher-owned writing/structure reference confirmed in approved `03` and STRICTLY conform to it.** Do not silently pick a new paper. Verify that it still matches the confirmed venue/track under `$expplan`'s precedence rules; if it does not, return to the two-reference confirmation gate. Venue match is the selection criterion, not topic: an exact-venue paper wins, then a sibling venue (e.g. EMNLP↔ACL↔NAACL, NeurIPS↔ICML↔ICLR), with topic/`task_type`/lineage only breaking ties. Fall back to a representative accepted paper only after the researcher explicitly approves that fallback in `$expplan`. The venue template from item 2 and length limit from item 3 still govern format.
   - **You MUST actually read its full text this run.** Her own papers are local in `researcher-profile/fulltext/txt/<key>.txt` (no fetch needed); a venue-fallback paper you web open/fetch (arXiv/anthology HTML). Never model structure "from memory" or from a generic template. If you cannot read the chosen reference, stop and say so; do not proceed on a guessed structure.
   - **Record a "Reference Conformance Block"** at the top of `main.tex` (as a comment) AND surface it to the researcher: the reference paper's real (a) ordered section/subsection list, (b) main-body **page count**, (c) figure list — count + what each depicts + which is Figure 1 + **each figure's POSITION/ORDER** (e.g. teaser at top of page 1, architecture/model figure beside the Method, results plots in Experiments), so the draft matches the reference's figure ORDER and placement and not only its count/kind — the model figure is defined in the Method section that introduces it, never dumped among the results floats, (d) table list — count + rows/cols of each, (e) **`figure_style`** — her figure conventions, so figures read like *hers*: **panel-label case** (e.g. lowercase `(a)/(b)` vs `(A)/(B)`), **caption format** (plain `Figure N: sentence.` vs a bold lead-in), **caption POSITION** — above vs below the float, measured **separately for figures and tables** but usually the same for both (this profile's reference puts BOTH below; feed it to the format gate as `--caption-pos below`), whether **acronyms are defined inline** in captions, **font family** (serif to match body), and the **colour palette** if a PDF is available to mine (if only extracted text is available, say so and use a restrained academic default rather than inventing one). This block is the evidence the step was done; skipping the fetch leaves it empty and visible.
   - **Match it strictly:** same section order and rough per-section length, **the same page count** (fill to it, do not stop at half the pages), the **same number and kind of figures** (if it has a threat-model diagram and an architecture figure, this paper has both), and result **tables laid out identically** (same rows=methods/attacks, cols=datasets/metrics, bold-best, ± std, caption style). Each of this paper's sections/figures/tables should map to a counterpart in the reference; note any deliberate deviation.
   - **Match per-section length, and MEASURE it from the reference — never guess a "class" band.** Run `python3 tools/paper_checks.py refshares --ref "researcher-profile/fulltext/txt/<key>.txt"` to get the reference's real per-section word shares, record them in the Conformance Block, and **seed `budget.json` from THOSE measured numbers**. Do NOT set the Experiments target from a vibe like "empirical papers put ~34% in Experiments" — that guess is exactly how Experiments balloons to 3 pages when the reference's Experiments section is ~23% (≈2 pages). Allocate each section to the reference's measured share; a section much shorter than its counterpart is under-written (expand it), one much longer is over-written (move content out).
   - **Mirror how the reference SPLITS empirical content — do not dump everything into Experiments.** A table-heavy empirical reference typically carries a large **analysis section** (its "Understanding …" §) that holds the mechanism findings, per-layer/qualitative analysis, and diagnostic tables, plus a separate, leaner **Experiments** §. Put analysis-type material (mechanism validation, per-layer, sensitivity, cost analysis) in the analysis section, and keep Experiments for the head-to-head + ablations, so the analysis/Experiments proportion matches the reference rather than a single oversized Experiments block.
   - **"Page count" means the MAIN BODY (Intro through Conclusion/Ethics), excluding references and appendices.** The body must reach the reference's body length (e.g. an ACL long paper is ~8 body pages); references and appendices come *after* that and push the total higher. Do not count appendix or reference pages toward the body target, and do not let a short body hide behind a long appendix.
   - **Reach the page count with SUBSTANTIVE content, never filler — a HARD delivery requirement.** Fill to the reference's body length by adding the material a real paper of this scope carries: a formal method statement with an algorithm block and the loss/objective written out, per-layer / sensitivity / qualitative / cost analysis subsections, a fuller Related Work, and appendices (implementation + hyperparameters, dataset construction, procedures in detail, extra result tables). Do NOT pad with restated sentences or vacuous prose. **The final PDF MUST fill to the target body page count**; the `length` gate (§Deterministic gates) measures this via the `endconclusion` label and stays red until the Conclusion ends at the bottom of the target page. The fill loop, the "compression not missing experiments" diagnosis, and the loop-back fallback all live in **§Scaffold & compile item 3** — follow it. Levers that add real height without padding: one subsection + its own float per `03` claim/experiment/ablation, split one big table into per-setting tables, add per-layer/sensitivity/qualitative tables, and include data figures at full `\columnwidth` (a bigger figure is legitimate height, see §Discipline · Figures).
   - **Dry-run figures: fill empty data-figure slots with clearly-labeled random data so they occupy real space.** When the venue reference has a figure/plot but this work has no real results yet (dry-run), do NOT leave the slot empty or a text box — generate the plot (pgfplots/matplotlib) with **synthetic/random values that follow the expected shape**, and mark it (caption or a visible tag) as dry-run/illustrative so it is swapped for real data later. This keeps the layout and page length faithful to the reference. (Architecture / concept diagrams are the exception — they are a schematic drawn by the `figureppt` skill, not random-data plots.)

## Step 2 — Outline & confirm (before any prose)

A short, explicit checkpoint that catches a wrong framing or structure **before** a single section is drafted — cheaper to fix an outline than a written paper. **Seed it from `03`'s §0(b) projected paper skeleton** (already approved at `$expplan`) — this step carries that plan forward and reconciles it with the venue reference's structure, it does not invent a new framing. After theorization (Step 1) and before Step 4 drafting, present a compact outline and **STOP for the researcher's confirmation** (this is a real gate — do not draft through it):

1. **Key information** — working **title**; the **2–3 core claims / contributions** (each one line, mechanism-anchored, and each pointing at the `results/` evidence that will back it); and a **one-paragraph story arc** (gap → idea → what the evidence shows). This is the paper's spine; if it is wrong, everything downstream is wrong.
2. **Method skeleton** — the **named modules** (the acronym and what each does, one line each) and the **section/subsection plan** for the Method, mapped to the confirmed formal spine from Step 1. Mirror the reference paper's Method organization (Overview + one subsection per module).

**Write it to `paper/outline.txt`** as a short bulleted plain-text outline (NOT prose), so the researcher can **edit it directly in the file**. Ask her to **confirm or edit**, then **read the (possibly edited) `paper/outline.txt` back** and write full prose only after she approves. If she revises it, re-read and re-confirm before drafting. Keep it brief — this is a sanity check on framing and structure, not the paper itself; `outline.txt` is a scratch file, not a numbered deliverable.

## Step 3 — Working abstract and interactive prose

After the outline gate, first establish a **working abstract contract**: a provisional abstract that states the motivation, precise gap, method, evaluation scope, principal supported result, and takeaway, using only result claims already supported by `results/`. Derive a venue-appropriate length band from the official rules when present and otherwise from the confirmed researcher-owned reference's measured abstract length; do not impose one universal word count. Materialize `paper/abstract_contract.json` with `min_words`, `max_words`, the derivation source, and one exact short `slot_evidence` phrase copied from the current abstract for each of those six rhetorical functions. Require all six functions rather than accepting an under-length abstract merely because it is grammatical. It keeps section conversations aligned, but is not final copy; rewrite it in Step 6 after the body stabilizes, refresh the evidence phrases, and recheck both completeness and the derived length band.

Then **always launch the repository's Paper Studio automatically**. Do not wait for another request for interactive writing, do not continue drafting competing prose in the coding-agent conversation, and do not merely print the command for the researcher to run. ## Personalization context (paperwrite OWNS it; threaded to every sub-skill)

Personalization is decided ONCE, here, and **passed down** — the sub-skills must not each
re-derive it independently, or they drift out of sync with the main draft (e.g. two skills
each inserting "≤3" self-cites for six total, or `papertheorization` grounding in a
different paper than the structural reference). When this skill invokes a sub-skill it
passes, and the sub-skill MUST honour over its own profile read, a **personalization
context**:

- **`reference_paper`** — the ONE own-paper structural reference chosen in Step 0, item 4 (its
  section structure, per-section length, table conventions, AND `figure_style` below).
  `papertheorization` grounds its formal spine in *this* paper, not a separately-picked one.
- **`self_cite_budget`** — a single shared running count, cap ≤3 for the WHOLE paper (defined
  in §Personalization.2). Every skill that adds a `\cite` to her own work draws from and
  decrements this one budget; `paperrelatedwork` does not open a second independent ≤3 cap.
- **`writing_style`** — the complete `paper/WRITING_STYLE.md` guidance (argument arc,
  section/paragraph architecture, contribution-bullet phrasing, experiment narrative,
  sentence mechanics, task-type variants, anti-imitation rules). Any sub-skill that writes
  prose (`paperrelatedwork`, the prose in `papertheorization`) receives and matches this
  shared guide, not a generic voice or a separately inferred style.
- **`figure_style`** — her figure conventions mined in Step 0, item 4 (palette, panel-label case,
  caption format, font). Applied to the data plots via `paper/fig/make_figs.py` (a committed
  `fig/style.py`) and to the `figureppt` model figure (label case/font + palette). See §Discipline · Figures.
- **`anti_self_plagiarism`** — the final near-duplicate pass (§Personalization.3) runs over
  ALL body prose INCLUDING sub-skill output, not only the main-line sections.

`paperlogiccheck` is the deliberate exception: narrative-logic checking is author-agnostic
and takes no personalization context. `papergapcheck` uses only `reference_paper`'s
Experiment Templates for cost estimates.

## Personalization (from the profile)

1. **Auto style-ref** — with no explicit style instruction, use `paper/WRITING_STYLE.md` as the detailed default (including its task-type variant and drafting checklist), then mirror the measured structure of the selected own venue-matched reference paper. The concrete reference paper and actual claim logic override generic tendencies; match cadence and organization without copying prior sentences.
2. **Self-citation (the one authoritative cap)** — `python3 tools/bib_manager.py selfcite --enriched "researcher-profile/publications.json" --draft paper/main.tex`; surface suggested own-paper cites for approval — **never auto-insert a `\cite`**. **Cap self-citations at ≤3 papers total for the whole paper (one shared `self_cite_budget`), and only the most relevant** (genuine method/lineage/baseline overlap); if the tool surfaces more, rank by relevance and propose only the top 3. Do not pad the reference list with the researcher's own papers.
3. **Anti-self-plagiarism** — compare each new contribution-bullet / abstract sentence against the researcher's prior abstracts (`publications.json`); flag near-identical sentences for rewrite, don't silently reuse.

## Discipline

- **Modular, section-by-section (W4)** — one section at a time, independently regenerable. Confirm the provisional abstract contract first; then draft Method → Experiments → Intro/Related and rewrite the final Abstract last.
- **Every number traces to `results/` (the one data-honesty rule).** Pull every number from a real result file; a value with no file → `[UNVERIFIED]`, never restated from memory, never fabricated. This rule governs tables, figures, gap-check, and the abstract alike — the places below reference it, they do not restate it.
- **Claims match the plan** — only claim what validated rows in
  `code/RESULTS_LEDGER.csv` and their rendered evidence in
  `reports/05_EXP_RESULT.html` support. `RUN_STATE.json` is not part of this
  workflow.
- **Scientific consistency contract.** Build `paper/scientific_consistency.json`
  from the approved plan's exact `consistency_requirements`, not a paper-chosen subset. Bind canonical
  terms, raw locators plus exact manuscript evidence, and each displayed formula
  to matching verifier evidence. Tables, captions, prose, plots, and configs reuse
  these values. `paper_checks.py consistency` and the executable formal check must
  pass; never repair drift with a paper-local alias or copied number.
- **Scholarship contract.** Follow `paperrelatedwork`'s clause-level citation audit,
  including Method/Experiments first-use citations and no section quotas. Materialize
  `paper/scholarship_contract.json` from every selected baseline, dataset, metric,
  external component, and sourced claim in the approved plan/paragraph map. Its
  citation obligations bind the exact supported clause and citation in one sentence and
  point to a retrieved local source excerpt that contains the support; its
  `setup_entities` give exact short evidence phrases showing what each dataset/method
  family is and why it tests a named claim or control; explain unique methods
  individually, otherwise group by family. `paper_checks.py scholarship` must pass.
- **Scientific prose boundary.** Keep paths, filenames, commands, JSON/result keys,
  ledger/canonical-artifact language, agent/Skill workflow, test harnesses, and internal
  repository architecture out of manuscript prose and captions. They may live in code,
  manifests, or reproducibility documentation. When implementation detail is
  scientifically material, describe the algorithm, interface, verification scope, or
  reproducibility condition in domain language without exposing the local workflow.
  Before approval, scan recursively expanded manuscript text and fail on leaked tokens
  such as local paths, script filenames, `results/`, `.json`, `.py`, or agent commands;
  inspect each hit because legitimate public package names are allowed.
- **Figures & tables follow the reference paper (Step 0, item 4)** — this is the authoritative figure/table spec; the `format` and `floats` gates enforce parts of it and reference here. Four kinds:
  - **Reference each artifact deliberately, never decoratively.** Bind every planned `F*`/`T*` to at least one load-bearing paragraph in `paper/paragraph_plan.json`. In each bound paragraph, include its exact `Figure~\ref{...}` or `Table~\ref{...}` once; forbid that artifact in unbound paragraphs and forbid repeated references within one paragraph. Default to one bound paragraph—and therefore one full-paper reference—per artifact. Add another binding only when that additional paragraph performs distinct analysis that genuinely depends on the artifact; never repeat the reference merely because the artifact remains visually or narratively nearby. Audit this mapping mechanically before the whole-paper gate.
  - **Encode presentation decisions as project data.** Give every figure an explicit rhetorical role, `width`, and `canvas_in` in `paper/paper_studio.json`; do not rely on the web engine to infer them from a section name. Paper Studio must only render and validate these writing decisions.
  - **Data plots** (ablation curves, bars, heatmaps) — generate them with a **committed Python/matplotlib script** (e.g. `paper/fig/make_figs.py`) that reads `results/` and writes a **PDF per figure** into `paper/fig/`, then include with `\includegraphics{fig/<name>.pdf}` (do NOT hand-inline pgfplots as the deliverable). Keep the script in the repo so every figure regenerates from data; under dry-run it uses clearly-labelled random data of the expected shape. **Call `fig.tight_layout()` before saving each figure** so ticks/labels/titles are never clipped. **Apply `figure_style`** via a committed `paper/fig/style.py` (her palette / serif font / panel-label convention), captions in her format (Step 0 figure-style record). **Figure text must be the venue BODY font size, never tiny:** generate each figure at the exact physical width it is `\includegraphics`'d at (1:1, no scaling) — set matplotlib `figsize` width in inches EQUAL to the include width (`\columnwidth`≈3.32in per AAAI column) AND `savefig.bbox='standard'` (NOT `'tight'`, which crops narrower so `\includegraphics[width=\columnwidth]` scales it UP and text renders LARGER than the body). Include data figures at full `\columnwidth` (not `0.72`). Base font **~9pt, slightly SMALLER than the body** (never tiny). After compiling, eyeball a figure against the body: figure text should be just slightly smaller.
  - **Architecture / method figure (the "model figure", usually Fig 2 after a motivation Fig 1)** — do NOT draw with matplotlib, and do NOT auto-author TikZ. **Invoke the `figureppt` skill.** Its mechanism: (1) a fixed "expert scientific-figure designer" meta-prompt is applied to the paper's Method text to GENERATE a **BioRender-style** image prompt; (2) an image model (gpt-image) draws the **imagery ONLY** (no text); (3) **use the gpt image as a design DRAFT and rebuild it as a FULLY-EDITABLE figure with `buildshapes`** — author `paper/fig/model_shapes.json` from the gpt draft, so EVERY element (icons as rounded-rects / ovals / hexagons, flows as arrows / connectors, text as boxes) is a native PPT shape individually editable. gpt still drafts the composition, but the `build` path (raster background + editable labels only) is NOT enough — its icons stay a non-editable raster. **The model figure must be as WIDE as the text block — a `figure*` spanning BOTH columns** with `\includegraphics[width=\textwidth]{fig/model.pdf}`, never a single-column half-width include. Set `buildshapes` `canvas_in` to a full-width banner aspect (e.g. `[7.0, 2.4]`). **After building, READ the rendered PDF and confirm it is page-wide and nothing is clipped.** Pass `figure_style` (panel-label case, font, palette). It is a BioRender-style schematic, NOT a flowchart of prose-filled boxes. **Flat design: no drop shadows, no gradients, no 3D bevels.** Until figureppt returns, leave the `\includegraphics{fig/model.pdf}` line commented with a one-line TODO. Define its float in the Method right after the paragraph that first `\ref`s it (see §Scaffold item 4 / the `floats` gate).
    - **Dry-run / no-image-model fallback (when gpt-image is unreachable — no `OPENAI_API_KEY`, sandboxed network, or `buildshapes` unavailable):** do NOT block the paper on it and do NOT leave an empty slot. Draw the model figure directly as **native matplotlib shapes** (`patches.FancyBboxPatch` / `FancyArrowPatch` / `Circle`) in a committed `paper/fig/make_model_fig.py` — a flat BioRender-style stage flow at the same page-wide `figure*` banner aspect (e.g. `figsize=(7.0, 2.35)`), the same `figure_style` palette/serif, math labels in real notation. It is fully editable and reproducible (regenerates from the script), so it is an honest stand-in for the figureppt output; note in the script docstring that it substitutes for figureppt in a dry run. READ the rendered PDF to confirm it is page-wide and unclipped, exactly as for the figureppt path.
  - **Opening / motivation figure (Fig 1)** — **the first figure is a MOTIVATION / concept figure**, not a results preview: it shows the problem and the core idea (e.g. a direct harmful request refused vs. the same goal succeeding once wrapped in a literary style), placed at the top of page 1 and `\ref`'d from the Introduction. **Do NOT preview experimental results in the Introduction** (results live in Experiments), even if the reference paper's own Fig 1 is a results teaser. Build it the same way as the model figure (gpt-image drafted, then rebuilt as fully-editable shapes via `buildshapes`), but **single-column (half width)** since it sits in the intro column, not a full-width `figure*`.
  - **Result tables** — laid out like the venue reference (rows=methods/attacks, cols=datasets/metrics, bold-best, ± std over seeds), `booktabs`; every cell traces to `results/` (see the data-honesty rule; a cell with no file → `[UNVERIFIED]`). **Match the reference's table WIDTH:** if its main results table spans both columns (a wide `table*`), the main table here is a `table*` too — a full, dense table (multiple models/attacks × defenses), not a cramped single-column one.
- **Refuse fabricated/synthetic inputs — or, in an explicit skill-test, watermark them loudly.** If `04_EXP_RESULT.html` / `results/` are watermarked SYNTHETIC or contain placeholder markers, say so and do NOT write them into the manuscript as real results. In a real run, stop. In an explicit skill-test / dry-run (fabricated data to exercise the pipeline), you MAY proceed, but ONLY if: (a) the compiled paper carries a **loud, unmissable banner** — `SKILL-TEST — fabricated data, NOT a scientific result` — visible on page 1 (e.g. a red `\fbox` under the title), not just a per-number `[SYNTHETIC]` mark; (b) every fabricated number keeps its `[SYNTHETIC]`/`\SYN` mark; and (c) the final summary to the researcher states plainly the data is fabricated. A skill-test paper must never be presentable as a real result. (The gates in AGENTS.md discipline #1 still apply — a test run does not skip the human's decisions.)

## Review sub-skills (this skill orchestrates them — do NOT skip)

`paperwrite` is the orchestrator. Four review sub-skills run **automatically inside
this skill's loop** (each is also invocable standalone as `/paper-<name>`). Do not make
the researcher call them by hand; call each at its point in the workflow, keep the
producer and the checker separate (spawn a fresh sub-agent for the checks that demand
it), and honour every honesty rail they enforce. **Pass each the personalization context
(above); the sub-skill honours it over its own profile read** — so the formal spine,
citations, prose voice, and figures stay consistent with the main draft.

1. **`papertheorization`** — before writing the Method/Analysis prose, decide the
   paper's formal spine: ONE unified object + 2–4 load-bearing results, each gated on
   necessity/usefulness/unity and **mechanically checked** (Lean if present, else
   `python3 paper/theory/verify.py` via sympy/numeric) before it is written. Ground it
   in her closest theory-`task_type` paper; write none if the work cannot support real
   theory — never decorate. For an `engineering`/`benchmark` paper a light spine
   (one definition + one proposition) is usually the right amount.
2. **`paperrelatedwork`** — when writing Related Work: reuse `reports/01_LIT_SURVEY.html`
   + her own entries in `publications.json` first, search only for gaps, **verify every newly-added arXiv id**,
   integrate under `\paragraph` subheadings (never a list dump), references filling
   ~2–4 columns. Draws from the ≤3 self-citation cap (§Personalization.2).
3. **`papergapcheck`** — in the refinement loop: walk every claim, map it to a file in
   `results/`, and for each hole either reserve a clearly-labelled pending slot or write
   it into `paper/EXPERIMENT_PLAN.md` (never fabricate a number — the data-honesty rule).
   Under the current SYNTHETIC dry-run its job is to confirm every claim has a real structural
   slot and every synthetic float is visibly marked, then list the real experiments
   the remaining `/goal` executions must produce.
4. **`paperlogiccheck`** — after a full draft compiles: build the section
   cross-reference map with `grep` (no external program), then **spawn a fresh
   sub-agent** to read the compiled PDF as a hostile reviewer and check each section's
   role, local support, understanding-cost, and that the Intro→Conclusion loop closes.
   Fix with bridge/signpost sentences; a genuine missing argument is routed back to
   `papergapcheck`, not smoothed over.

**Order in the loop** (this is Step 1 → Step 9 of the Step 0–10 map at the top): theorization → Method/Experiments → related-work → Intro/Abstract → compile → deterministic gates → gap-check + logic-check → fix/recompile/re-check. This agentic loop runs alongside the mechanical compile/length-diff loop below.

## Deterministic gates (`tools/paper_checks.py` — the paperkit-equivalent, don't skip)

The agentic checks above are paired with **mechanical gates** so the draft cannot merely
*claim* venue-readiness. Run `python3 tools/paper_checks.py all --paper-dir paper
--venue-pages <N> --body-target <ref-body-pages> --caption-pos <below|above>` after each
compile (set `--caption-pos` to the reference's measured convention, Step 0 figure-style record — this profile:
`below`); it emits JSON with an `ok` per check and exits non-zero until every gate is green:

- **budget** — per-section word-share vs `paper/budget.json` (±3%), seeded from the reference's
  **measured** shares (`refshares`, Step 0, item 4) BEFORE drafting, never from a guessed "class" band.
  **Do NOT assume Experiments is the largest block:** in an analysis-driven paper (like this
  profile's reference) the mechanism/analysis section is largest and Experiments is ~0.23. **The
  Conclusion share is small** — the reference's conclusion is one short paragraph (~2% of body), so
  cap it there; a fat Conclusion is a red flag, not length. Re-checked after every content edit so
  expanding one section cannot silently steal proportion from another.
  **When budget and length conflict, LENGTH WINS; budget is secondary** (the researcher's call,
  2026-07-26). Filling to the target page is the hard delivery requirement; the per-section shares are
  an advisory shape. So never SHORTEN the body to satisfy budget if that drops the Conclusion off the
  target page. Resolve a conflict by MOVING words between sections (from an over-share section into an
  under-share one), not by adding/removing net length — that fixes the proportion without disturbing the
  page fill. If a section is legitimately over its share but the paper's structure warrants it and
  length is satisfied, leave it and note the deviation rather than gutting content to hit the band.
- **style** — LLM-tell budgets per 1k body words (em-dash/paren/`\textbf`/`\emph`), **zero
  contractions**, a body **equation floor** (≥4), and **no bullet/numbered lists in the body**
  (`\begin{itemize}`/`\begin{enumerate}` are flagged — write contributions and lists as prose).
  Bold/italic are barred as body emphasis (headings exempt); a long section with no `\paragraph`
  subheading is flagged. The same gate rejects internal workflow/path leakage from
  manuscript prose and checks the final abstract against its recorded rhetorical slots
  and venue/reference-derived length band.
- **length (the authoritative fill mechanics)** — judged by **WHERE THE CONCLUSION ENDS, not a page
  count**. The venue-counted content (Intro..Conclusion) must end **on the target page, at or near its
  bottom** (the ACL 8th page): not a page earlier (under-written), not later (over the limit), not
  high-on-the-page (page 8 half-empty with Limitations/Ethics sharing it). **The bottom does NOT have to
  be pixel-exact — ±5 lines is acceptable** (the researcher confirmed this, 2026-07-26; float repacking
  makes the last line jump by more than a small edit, so exact-bottom tuning is a waste). Put
  `\label{paper:endconclusion}` at the very END of the Conclusion and `\label{paper:limstart}` right
  after `\section*{Limitations}`; the gate requires `endconclusion == target` AND the following section
  to start on `target+1` **OR within `LENGTH_LINE_TOL` (5) lines of the target-page bottom**. **For a
  venue with NO Limitations section (e.g. AAAI)** the same ±5-line tolerance applies to where References
  start. `conclusion_not_at_page_bottom` means the counted content is short by MORE than 5 lines.
  **CRITICAL — fill from the BODY, never by padding the Conclusion:** the Conclusion stays as short as
  the reference's (see the budget cap); when it ends well above the page bottom, add analysis/experiments
  content or MOVE a discussion paragraph into the analysis section — do NOT bloat the Conclusion.
  **FREEZE THE FLOAT COUNT BEFORE tuning body length.** Length tuning is unstable while floats are still
  being added/removed: each new/removed table or figure repacks every float and jumps the Conclusion's
  end by more than a sentence edit, so you chase your tail. Sequence it: (1) settle the full float set
  (every `03` claim/ablation has its table/figure, model figure placed), (2) THEN adjust prose length in
  small moves; if a small trim/add does not move the boundary, it is float repacking, not your edit —
  stop micro-editing and accept anything within the ±5-line band. **Confirm visually** that the
  Conclusion's last line sits at/near the page bottom (total pages / a long appendix never substitute).
  The approved embedded contract, not the current `.tex`, defines the frozen float set.
  Never delete, merge, or relabel a planned artifact to make the length gate
  green. Under page pressure, move only artifacts marked
  `body_or_appendix`; otherwise trim/rebalance prose or return to `$expplan`
  for explicit approval of a structural amendment.
- **formal** — `paper/theory/verify.py` (or a `.lean`) exists, body carries the equations,
  a derivations appendix is present (pairs with `papertheorization`).
- **format** — no overfull hboxes (from the log), `\widowpenalty=\clubpenalty=10000` set, a dense/wide
  results table is a full-width `table*`, and **caption position matches the reference for figures AND
  tables** (`--caption-pos below|above`, Step 0 figure-style record — this profile BELOW, so `\caption` goes AFTER
  `\end{tabular}` and AFTER `\includegraphics`). The full figure/table spec these checks enforce lives
  in §Discipline · Figures.
- **floats** — every figure/table is DEFINED in the source at/near the section that first `\ref`s it, and
  figures appear in first-reference order. Flags `float_defined_after_its_reference_section` (classically
  the model figure `\ref`'d in the Method but its `\begin{figure}` dropped among the results floats, so it
  renders a section too late) and `figures_out_of_first_reference_order`. Full placement rules: §Scaffold item 4.

**Never lower a threshold or edit `budget.json` to make a gate pass** — fix the paper. A
gate that is green only because the bar was moved is worse than an honest red. If a
requirement is genuinely unsatisfiable with honest content, say so at the GATE with the
specific shortfall (e.g. "body 6/8 pages after filling every substantive slot"). Thresholds
live at the top of `paper_checks.py`; tune them once for the venue, not per-draft to dodge a
failure.

## Scaffold & compile (paper/ must build)

1. **Scaffold on first run** — if `paper/` is absent, create it from the venue template: `main.tex` (venue `\documentclass` + complete section skeleton), `references.bib` (seed via `bib_manager export` from `publications.json`), and drop the venue `.sty`/`.cls` alongside. Also create `paper/paragraph_plan.json` and `paper/paper_studio.json` from the approved skeleton/artifact contract before launching Paper Studio; give a genuinely new writing run a new stable `project.id`, configure all section/Figure/Table/result bindings, and validate both files through the `paperstudio` skill. `main.tex` must `\input` every configured section from the start—even while its file contains only an awaiting-draft comment—and must place `sections/abstract` inside the venue's `abstract` environment. Never leave a post-outline placeholder that compiles only the title page, and never accept “compiled” as proof that accepted prose appears in the PDF; extract PDF text to verify it. Never overwrite an existing `paper/` (W3); write new sections in place.
2. **Compile after each section (and at the end)** — run `latexmk -pdf -interaction=nonstopmode -halt-on-error paper/main.tex` (the toolchain is installed: `pdflatex`/`xelatex`/`latexmk`).
   - **Builds** → report "compiled, N pages" + the current-vs-limit page count (Step 0, item 3).
   - **Fails** → extract the real errors from `main.log` (missing package, undefined `\ref`/`\cite`, bad bib key) and fix them; do not leave a `main.tex` that does not build.
   - **Known build gotchas (hit these repeatedly — check them first):**
     - **`bibtex: Illegal, another \bibstyle command`** — `acl.sty` (and most venue styles) already emit `\bibliographystyle`. Do NOT add your own `\bibliographystyle{...}` line; keep only `\bibliography{references}`.
     - **`savefig.bbox='standard'` is an rcParam, not a `savefig()` kwarg.** Passing `bbox_inches="standard"` raises `AttributeError`. Set it once via `matplotlib.rcParams['savefig.bbox']='standard'`; use `fig.tight_layout()` before saving (never `bbox_inches='tight'`, which crops and upscales figure text).
     - **Overfull `\hbox` from wide display math** — a two-part definition or a `\dcross=…,\ \mathrm{VG}=…` on one `\[...\]`/`equation` line overflows the column. Split into `align`/`align*` with `\\`, or shrink fractions with `\tfrac`. The `format` gate flags these.
     - **`latexmk` state corruption** after a manual `rm main.aux` — run `pdflatex`×2 + `bibtex` directly, or `latexmk -C` then rebuild, to rebuild cross-references.
     - **`budget.json` shape** — the budget gate reads section names as TOP-LEVEL keys; do not nest them under a `"sections"` object or every section reads as missing.
     - **Zsh word-splitting** — an unquoted `$FILES` string variable is NOT split into words in zsh; use a proper array `FILES=(a b c)` for `for f in "${FILES[@]}"`.
3. **Diff the compiled PDF against the reference paper — required, not optional.** The primary length test is the `length` gate's `endconclusion`/`limstart` mechanics (§Deterministic gates) — total pages, refs, and a long appendix never substitute, and neither does a padded Conclusion. Compare the rendered `main.pdf` to the reference's Conformance Block (Step 0, item 4) on: (a) **where the Conclusion ends** — the single most important axis; (b) section order + per-section page share, including that the Conclusion is no longer than the reference's; (c) figure count/kind **and ORDER/POSITION — the model figure appears beside the Method it introduces (Fig 2 near §3), not after the results teaser; run `paper_checks.py floats`**; (d) table count/layout/width **and caption position**. Report the diff explicitly (e.g. "BODY 6.5 / 8.0 pages, Experiments 3 thin paragraphs vs the reference's 5 subsections + 4 tables"). Then run the fill loop:
   - **If the body is short, the usual cause is COMPRESSION, not missing experiments.** `reports/03_EXPERIMENT_PLAN.html` already designed the full claim set + ablation matrix — a whole paper's worth. A short body means you wrote each as one thin paragraph instead of the reference's way: **one named subsection per claim/experiment/ablation, each with its own table or figure and a real analysis paragraph** (per-layer, sensitivity, qualitative, cost). Match the reference's **CONTENT table/figure COUNT**. Never combine two embedded-contract artifacts into one aggregate float: per-game and per-model tables remain separate when separately approved. **Do NOT make the experiment setup a table — write backbones / datasets / hyperparameters / graph settings as prose in the Settings section.** Pull every row of 03's claims table and ablation matrix into the body as its own float + prose. Recompile and rerun plan conformance. Do NOT reach for filler, add experiments 03 did not design, or compress away an approved artifact.
   - **Fallback when the body is genuinely short after exhausting 03 — loop back to `$expplan`, then `$runplan` and its `/goal` sequence; do NOT pad.** When every `03` claim / experiment / ablation is already its own subsection + float, every analysis axis (per-layer / sensitivity / qualitative / cost) is present, and the body STILL cannot reach the target page, the honest cause is that the experiment set is too small for the venue — not the writing. **Stop the fill loop and route the shortfall back through the pipeline**: (1) state the gap at the GATE with numbers ("body 7/8 pages; N floats vs the reference's M; too few experiments to fill an 8-page venue"); (2) **re-open `$expplan` to add the missing experiments** — more datasets, baselines, ablation rows, sensitivity/robustness sweeps, analysis tables — updating `reports/03_EXPERIMENT_PLAN.html`; (3) **use `$runplan` to rebuild the execution graph, then manually execute its proposed `/goal` commands** to produce new `results/`; (4) **resume `$paperwrite`** and write the new results up as their own subsections + floats. Padding is never the fix — a page filled by padding is worse than an honest "N/8 pages, experiments under-scoped, expanding via $expplan". If the researcher explicitly asked for a **micro / smoke / test run**, do not silently pad either: report the honest fill (e.g. "6.5/8 body pages; filling to 8 needs a full experiment set this test run deliberately lacks") and stop, leaving the scale-up to an explicit follow-up. This mirrors the `$expplan` §0 part (c) page-fill feasibility check, which catches the shortfall *before* writing; this fallback catches it if it slips through.
   - **Arrange the section layout UP FRONT so the length is reachable** — before drafting, allocate body sections + subsections + one float per 03 experiment against the reference's per-section shares (Step 0, item 4) so there is a real slot for every page. Body prose is continuous — **no bullet lists**.
4. **Float placement — no all-float page, order tracks the text (the authoritative placement spec; the `floats` gate enforces it).** Place each figure/table in the source **right after the paragraph that first references it**, never in a block at the end of a section — a block of floats cascades onto a **float-only page** and breaks reference order. Rules: (a) source order = first-reference order, so float numbers increase in the order the text discusses them; (b) single-column tables use `[tb]` so LaTeX can distribute them, wide `table*`/`figure*` use `[t]`; (c) after compiling, read float→page from the `.aux` (`\newlabel{tab:..}{{}{PAGE}}`) and the PDF — if any page is all floats, or two+ floats stack with no text between them, move a float to its reference point or convert to `[tb]`; (d) keep at most ~one wide float per page; (e) **every float DEFINED at/near the section that first `\ref`s it, figures in first-reference order** — the classic bug is the model figure `\ref`'d in the Method but its `\begin{figure}` left among the results floats. `python3 tools/paper_checks.py floats` flags `float_defined_after_its_reference_section` and `figures_out_of_first_reference_order` mechanically (part of `paper_checks.py all`).
5. **Output the PDF** — `paper/main.pdf` is a deliverable alongside the source, at the reference's body length (within the venue limit).
