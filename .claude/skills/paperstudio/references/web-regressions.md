# Paper Studio product and regression contract

## LLM API setup

- The terminal writing workflow selects only OpenAI or DeepSeek before launching
  Paper Studio; the webpage shows runtime status but no persistent API/model settings panel.
  Read their secrets only from `OPENAI_API_KEY` or `DEEPSEEK_API_KEY`.
- When the selected provider is not configured, show one prominent page-level banner that says the key is
  entered in the local terminal that starts Paper Studio, gives the export and
  restart commands, and warns against pasting the secret into chat, repository
  files, or browser storage.
- Public state and the DOM may expose configuration status and instructions,
  never the key value. GPT endpoint errors must repeat the actionable setup
  location instead of returning a generic English missing-key error.
- Persist the selected provider and editable model. Switching providers resets
  section, title, and figure-Prompt conversation IDs and applies the provider's
  default model. Never send a response ID from one provider to another.
- GPT Image remains OpenAI-only and continues to require `OPENAI_API_KEY`.

## Data figures

- Generate and show every requested plot as a PDF candidate. Do not expose generated Python source or a plotting-code block in the browser.
- Keep running progress inside the corresponding figure/panel card. Preserve keyed cards and iframe nodes while polling; do not rebuild PDF iframes on every render or let completed PDFs continue flickering.
- A figure with exactly one panel is a standalone figure:
  - Display `F<n> · title`, never `F<n>(a)`.
  - Say “图”, not “子图”.
  - Use only the main figure candidate preview; do not render a nested `.data-panel` card or a second empty preview.
  - Show exactly one generation button for the figure.
  - When the figure is ready, pending, and has no candidate, automatically start its one plotting job once on first display. Never auto-retry a failed job; retain the button for manual retry.
  - Hide the composition Prompt, layout-plan details, and compose button.
  - Generate the final no-label PDF/PPTX candidate directly after the one plotting job.
  - Never add `(a)` or any panel label.
- A figure with two or more panels uses a manual staged workflow:
  - On first display, if no panel candidate exists, automatically generate every pending panel in configured order. Run one local-Agent panel job at a time; finishing panel a starts panel b only after a reaches `built`.
  - Record one auto-attempt per panel. Never auto-retry a failed panel; retain each panel's manual retry button.
  - Finishing the last panel must not start composition.
  - Show every panel candidate before composition.
  - Before the first composition, label the button `合成图`; only after a composed candidate exists use `重新解析 Prompt 并生成合成图`.
- For a multi-panel figure, render the complete panel editing units in configured order first (`a`, then `b`, and so on), then render one grouped composition editor containing `论文组合 Prompt`, the compose action, and the parsed layout plan. The Prompt starts blank; do not insert “candidate” text or implement placeholder/right-click activation tricks. User text is ordinary editable input and must survive unrelated renders. Do not add a separate Prompt confirmation/save button: the current text is consumed when the researcher clicks `合成图` or recomposes.
- Preserve each unsaved panel Prompt and composition Prompt browser-locally under project ID plus figure/panel ID across polling, artifact/section/view switches, and refresh. Restore the server's saved `agent_prompt`/`layout_prompt` when clean; never clear a saved composition Prompt merely because the figure tab was reopened.
- Do not render a generic empty preview block such as `生成后在这里检查构图或数据图`. Before a candidate exists, show only the relevant generation/editing controls; after it exists, show the actual image/PDF preview.
- Compose panels as independent vector PDF objects in an editable PPTX, add requested labels at sensible physical sizes, export the same layout to vector PDF, crop exterior whitespace, and avoid unintended inter-panel gaps. Do not depend on manual PowerPoint permission clicks.
- Do not show “下载该子图 PDF”; candidates are already local. Show the embedded PDF and retain local files.
- Only reveal `确认并插入正文` after the final composed PDF has actually loaded. Place it after the insertion-position and layout-mode row. After approval, label it `重新插入`.
- Do not depend solely on a PDF iframe `load` event: headless/native PDF viewers may omit it, and cached files can finish before a late handler is attached. Bind the handler before assigning `src` and perform a same-origin fetch availability check as a fallback. Mark the exact figure/URL loaded only when either succeeds; a missing or failed PDF must keep insertion locked.
- Show the current figure caption directly below the final candidate preview. Keep it editable and persist one caption value that is shared by the browser, bound-artifact GPT context, and the final LaTeX `\\caption{}`. If an already-approved caption changes manually or through a GPT candidate, immediately mark it unsaved, relabel the bottom action from disabled `已插入正文` to enabled `更新 Caption → PDF`, and submit the visible textarea value when clicked. Re-render and compile transactionally, rolling back on failure; clear the exact visible input's dirty state before rendering a successful response, then restore `Caption 已写入正文与 PDF` and disabled `已插入正文`. A server success message with a still-dirty button is a UI transaction failure. The separate Caption save action must perform the same transaction and clearly say it updates the PDF.
- Give the caption its own researcher-authored GPT Prompt field and generation button. GPT receives the current caption, figure/panel semantics, layout, and exact bound result values; it returns an editable caption candidate but must never save or insert it automatically. Preserve required evidence markers such as `[SYNTHETIC]` deterministically.
- Preserve an unsent Caption GPT instruction under project ID plus artifact ID across unrelated renders, artifact/section/view switches, and refresh. Clear it after Caption generation succeeds or exact revert to blank.
- Store unsaved manual and GPT Caption candidates browser-locally under project ID plus artifact ID. Preserve each independently across GPT/PPT preview toggles, polling renders, figure/section/view switches, and refresh; switching to another artifact must never replace a dirty Caption with its canonical server value. Clear a draft only after its own successful save/compile or when the visible text exactly equals the canonical Caption. Never let one project's draft appear in another project.
- Keep the figure-editing page in one top-to-bottom workflow: figure modification/generation Prompt and controls; final candidate preview; editable Caption and Caption GPT Prompt; insertion position and layout; confirmation. Never put figure-modification controls below Caption or below insertion controls.

- Present mechanism Prompt editing as a clear two-column workbench on desktop: the complete GPT-generated BioRender design Prompt on the left and the researcher's Prompt-modification instruction on the right. Keep the update action inside the instruction card so its input/output relationship is obvious; stack the cards only on narrow screens.
- Put the next action immediately below that workbench, before the preview: a compact live flow showing `设计 Prompt → GPT Image → 可编辑 PPT/PDF`, with pending, active, and completed states derived from the real figure job. Place `确认 Prompt → GPT Image` and the manual editable-build retry in this same stage. Do not separate the confirmation button or process explanation from the Prompt editor with unrelated controls.
- Store unsaved design-Prompt and modification-instruction edits browser-locally by project and figure. Preserve them independently across GPT/PPT preview toggles, polling renders, figure/section/view switches, and refresh; reconcile a field only when its exact value has become canonical on the server or the researcher reverts it exactly.
- Drive actions from the visible Prompt fields, not stale canonical state. A researcher may paste a complete design Prompt into an initially empty editor and draw immediately. Once a design Prompt exists, require a nonempty modification instruction before enabling the GPT Prompt-update action; re-evaluate both buttons on every input.

## Placement and paper layout

- Always populate insertion-position options from every paragraph in the bound section. Mark unfinished entries visibly and disable them if insertion is not yet safe; never render an empty select.
- Put layout mode beside insertion position. Support single-column and two-column figures. Show Wrapfigure as unavailable when the active venue template forbids it; reject it server-side with a clear explanation.
- Map single-column to `figure` plus `\columnwidth` and two-column to `figure*` plus `\textwidth`. Recompose a data figure at its new physical width when layout mode changes.
- Insert approved floats after the selected paragraph and compile transactionally. Roll back source/state when LaTeX fails.
- After insertion, keep the placement and layout controls populated and visibly selected. Show `已插入正文` with the persisted target (for example `E3 后`) and layout mode in that same placement row, and change the approval action to `重新插入`; never replace the controls with an empty or detached status card.

## Prose editor and configured artifact bindings

- Keep the prose editor focused on paragraph selection, reference context, candidate text, and revision controls. Do not show a separate `系统确定的段落任务`/purpose card in the browser; purpose metadata remains internal grounding for GPT.
- A completed section must remain inspectable and editable. Keep its final accepted paragraph selected instead of exposing a null current paragraph, so its matched reference excerpt, accepted text, and paragraph navigation remain visible. Do not treat that accepted final paragraph as an ungenerated “next paragraph” or automatically regenerate it after Accept.
- On refresh, an accepted paragraph with no new candidate must show its accepted text and a disabled action labelled `已写入 LaTeX`, not a disabled `Accept → LaTeX` that implies an unfinished write. Explain that the researcher can enter a comment, generate a new candidate, and then Accept again. A pending paragraph with no candidate uses `等待 candidate`; only a real candidate enables `Accept → LaTeX`.
- Accepted prose remains directly editable in the same candidate textarea. Preserve each unsaved edit browser-locally under project ID plus section/paragraph ID across unrelated renders, paragraph/section/view switches, and refresh. Retain the original canonical baseline for stale-write detection, enable `Accept → LaTeX` when the visible text differs from it, reject a stale baseline, and compile the researcher-edited text transactionally. Clear only after successful Generate/Accept or exact revert. Do not require a GPT round merely to correct accepted prose.
- On every prose GPT turn, place the exact current nonempty researcher Prompt in a final, explicit primary-editing-objective block and instruct the model that it outranks the current draft, reference style, and generic prose preferences. Require complete literal execution of every nonconflicting requested change; never silently weaken, reinterpret, omit, or preserve contrary prior text. Keep only the hard contracts from `/paperwrite` above it: evidence honesty, verified citations, configured artifact bindings, required headings, synthetic markers, and valid LaTeX. These are implementation guardrails, not a second source of writing policy.
- A nonempty prose revision comment must not create a fake new candidate whose text is unchanged. If GPT returns the normalized current candidate verbatim, continue once in the same response chain with an explicit no-op correction that repeats the researcher instruction. Re-run all normal LaTeX, citation, heading, and artifact-reference validation; if the final text is still unchanged, return a visible error and persist neither a new candidate nor candidate history entry.
- Preserve each unsent prose revision comment independently under project ID plus section/paragraph ID across paragraph/section/view switches and refresh; never move one paragraph's comment into another. Clear it after Generate/Accept succeeds or exact revert to blank.
- Store unsaved title and Title GPT Prompt text browser-locally under the project ID. Preserve both independently across section/view switches and refresh; neither is authoritative until its own server action succeeds. Clear a field only after that successful transaction or exact revert to the canonical value.
- Normalize JSON-style doubled backslashes before known LaTeX manuscript commands (`\\cite`, `\\ref`, headings, emphasis, URLs) when GPT text enters the workflow and again before Accept. Preserve unrelated `\\` sequences. Compile and extract PDF text in regression tests so escaped commands cannot silently appear as the words `cite` or `ref` in the paper.
- Validate every planned `reference_lines` range against the exact Python `splitlines()` representation used by the server, including form-feed page breaks from PDF extraction. A range must be nonempty and begin in the intended reference section/paragraph rather than silently drifting into adjacent content.
- Before Accept → LaTeX, fetch the latest server state and reconcile the visible paragraph/candidate. If only the candidate ID changed while its text is identical, safely accept the latest ID. If the text or current paragraph changed, render the latest state and require the researcher to review and click Accept again. Never accept unseen text, require a manual reload, or expose an English `candidate is stale` error. The server must also tolerate an equivalent-text ID race and reject a different-text race with an actionable Chinese message.
- A persisted candidate must remain acceptable even if its section `previous_response_id` is missing after a conversation reset, migration, or partial-state recovery. If citation resolution is required, start a new citation-resolver chain from the complete candidate, section/purpose context, and verified bibliography; do not strand the candidate with “section conversation 不存在” or force the researcher to regenerate unchanged prose. Store the new resolver response ID for later turns.
- After Accept → LaTeX returns a successful compiled state, update the paragraph state, status message, and vector-page PDF viewer immediately. Only then may the client request the next paragraph candidate. The second GPT request must not postpone, blank, or hide the compiled PDF; its progress must be explicit, and its failure must report that acceptance/compilation already succeeded.
- Compile success is valid only if `paper/main.tex` includes every section file configured in `paper_studio.json`. The Abstract input must be inside the LaTeX `abstract` environment. Reject a scaffold that merely compiles its title page while silently omitting accepted section content; browser-test that accepted Abstract text is present in extracted PDF text after refresh.
- Model section-internal grouping explicitly in `paragraph_plan.json` with `heading` plus `heading_style`. Use run-in `textbf` group headings for Related Work and structural `subsection` headings for Experiments and other multi-module technical/result sections. Add a heading only to the first paragraph of its group, and deterministically preserve the exact planned LaTeX command through GPT drafting, citation repair, state reload, Accept, and section re-rendering.
- Show figure-to-paragraph and table-to-paragraph bindings only as compact markers such as `◆F4` or `◆T1` inside paragraph buttons. Do not add a separate `关联图/关联表 · ID · title` card in the prose editor. Deduplicate artifacts by ID.
- Bind prose through explicit `paragraph.artifacts`; never guess bindings from paragraph titles or from letters such as F/T.
- On every GPT draft or revision, include each bound artifact's ID, kind, title, description, caption, panel semantics, LaTeX label, and exact required reference (`Figure~\ref{...}` or `Table~\ref{...}`). Include traceable section evidence.
- Treat every bound reference as mandatory. If GPT omits one, issue one corrective continuation in the same conversation. If it still omits the reference, surface an error instead of silently accepting nearly identical prose.
- Enforce, but do not author, `paragraph.artifacts`: each configured binding requires one exact reference in that paragraph and each unlisted configured artifact requires zero. `/paperwrite` decides the bindings and their writing rationale. Apply the deterministic audit after every GPT rewrite/citation repair and before Accept so direct edits and recovered old candidates cannot bypass project data.
- Keep figure/table definitions and first references consistent with paragraph-plan order.

## Result-schema honesty

- Compare server `result_keys`, panel `result_keys`, the embedded approved experiment-plan contract, and actual `results/` paths. A stricter accidental key is a bug; weakening a real approved requirement is not a fix.
- Never fabricate numeric curves, cells, or defaults by default. Only when the researcher explicitly requests invented data for a synthetic workflow/test may it be created; store `synthetic: true` plus a notice in `results/`, watermark the figure visibly as synthetic/not measured, mark the caption, and never present it as a real result. Otherwise, when the source only states qualitative robustness, create a visibly qualitative evidence-coverage candidate and state that numeric curves are unavailable.
- Keep gates actionable: distinguish missing data, missing prerequisite prose, missing prerequisite figures, missing local packages, and a failed Agent job.
- Separate candidate-generation gates from insertion gates, and read their prose requirements from project data. Use each mechanism figure's `generation_requires_paragraphs` map: intro/motivation figures may require only the first citing paragraph, while model/method figures should require all subsections needed to define the complete architecture. Do not infer the role from a figure ID, title, or section name.
- A GPT-drawn mechanism candidate uses the archived GPT Image only as a visual reconstruction reference. The final PPTX must rebuild every module, icon, arrow, and label as independently editable native objects through `buildshapes`; its matching paper PDF comes from `pdfshapes`. Reject any `ppt/media/` raster layer, fewer than 12 native objects, fewer than four modules, or fewer than two connectors. Also reject generic title-plus-description placeholders.
- Derive the placeholder location independently from the first ordered `paragraph_plan.json` `artifacts` binding. As soon as that first citation is accepted, render a compilable placeholder float with the figure's real current Caption and formal `\\label`, so `Figure~\\ref{...}` resolves before the artwork exists. The placeholder does not bypass `generation_requires_paragraphs`: a model figure can remain blocked until its configured Method subsections are complete.
- Before the mechanism Prompt workbench, show an explicit prerequisite notice whenever configured prose is missing. Name the exact missing headings and say `请先生成并写入 <section> section 的 <heading> subsection，然后再画图`; disable Prompt generation, GPT Image, and editable rebuild in both the DOM and server endpoints. List only still-missing subsections.
- When GPT Image returns successfully, continue the same background job automatically through Agent-grounded shape reconstruction and PPTX/PDF generation, then finish in `built`; do not stop at `draft` and force a second click. Expose manual generation only for retrying a failed build or deliberately rebuilding existing deliverables. While rebuilding, relabel the retry action as running and explicitly say that the GPT/PPT toggle appears only after the paper version finishes. On failure, show the actual rebuild error beside the preview instead of silently withholding the toggle. The final `确认并插入正文` remains separate and becomes enabled once the packaged PDF/PPTX exist, configured prose requirements are accepted, and non-prose dependencies pass. Confirmation replaces the placeholder with the real PDF while preserving the same Caption and label. Treat `depends_on_paragraphs` as eventual float-placement anchors, not a requirement that every listed paragraph be accepted first.
- Hide the manual editable-build action during the initial pending, GPT Image, automatic reconstruction, and completed stages. Reveal `重试可编辑 PPT/PDF 重建` only after a real reconstruction failure with an archived GPT draft. A completed paper version needs no separate rebuild action; changing and confirming the drawing Prompt starts the full automatic pipeline again.
- Before every GPT Image request, compare the submitted Prompt with the exact archived Prompt that produced the current draft. If they match after trimming outer whitespace, reuse the draft and all current artifacts, preserve approval state, create no new iteration, and report that no GPT Image call was made. Enforce this on the server so repeated clicks or direct HTTP calls cannot incur duplicate image cost.
- When both mechanism candidates exist, default the main preview to the final paper-sized PPT/PDF rendering and reveal a single toggle labelled `显示 GPT 原图`; in GPT mode relabel it `显示 PPT/PDF 版`. Switch the existing preview surface rather than stacking two previews. Hide the toggle unless both versions belong to the current completed build, and never let the preview choice affect insertion or persisted manuscript state.
- Pass configured placement/canvas values into GPT prompt generation without inferring a figure's rhetorical role in the web engine. Browser-test both supported widths and their LaTeX mappings; `/paperwrite` owns which width a particular artifact receives.

## Global local-Agent chat

- Keep a fixed `?` launcher visible at the lower-right of the webpage in writing, figure, and table views.
- Open a modal chat on click; support close button, backdrop click, and Escape. Restore the launcher after closing and focus the input after opening.
- Maintain one global chat history and send the current section, view, and selected artifact as context. During a read-only question/advice turn, the local Agent must not claim it clicked buttons or changed files.
- The global chat is executable when the researcher gives an explicit safe action command such as add, modify, move, fix, generate, or compile. Run local Codex with workspace-write access, require it to read this skill and contract, make real repository changes, validate them, reload Paper Studio state in the same response, and record the exact changed source files. Questions and requests for advice remain read-only. Deletion, clearing, broad overwrite, and similarly destructive changes must return `等待确认` and execute only after an explicit confirmation turn.
- Let Codex itself classify each ordinary turn semantically from the current message and recent history, returning structured `read_only`, `execute`, or `confirmation_required` intent. Do not use an action-verb whitelist to decide whether natural imperatives, indirect requests, examples, questions, or retry turns may write. Give non-destructive turns a write-capable sandbox so Codex can act when its semantic judgment is `execute`; require it to make no changes when its judgment is `read_only`. Keep only a deterministic server-side confirmation gate for deletion, clearing, broad overwrite, and similarly hard-to-recover operations.
- Execution provenance must fingerprint researcher-visible PNG/PDF/PPTX/SVG outputs under `paper/` as well as text sources, so an artifact-only operation is not mislabelled as unchanged. Run each Codex turn in a separate process group; on timeout, terminate the entire group before reporting failure so no orphaned subprocess can finish a supposedly failed edit later. If an idempotent execution finds that the requested state already exists, label it `已处理 · 无文件变更` rather than falling back to read-only or claiming failure.
- Show deterministic execution provenance on every new Agent bubble: `仅回答`, `已执行 · N 个文件`, `等待确认`, or `未执行成功`. Never label a turn executed unless source fingerprints prove that files changed; if an explicit action produces no source change, say so rather than presenting advice as execution. Structural manuscript actions must update `paper/paragraph_plan.json` (and use valid unique IDs, grouping styles, and reference ranges) so the browser immediately exposes the new work item; never edit `.paper_studio/state.json` directly.
- Keep structural Agent edits canonical and non-duplicating. Adding a planned paragraph/subsection must update `paper/paragraph_plan.json` and let the normal candidate → Accept workflow render section LaTeX; do not also append the same prose directly to `paper/sections/*.tex` while leaving that plan item pending. If an Agent changes manuscript source explicitly, reload and reconcile the browser plan/status before reporting success so a later Accept cannot duplicate or overwrite the change.
- Run executable global-chat turns as persisted background jobs. The POST must return immediately, append the user turn once, show an in-round `执行中` Agent bubble, poll state until completion, and keep the modal closable and the rest of the webpage responsive. Disable duplicate sends only while that job is running. After a server restart, mark an orphaned running job failed with an actionable retry message instead of leaving the browser permanently busy.
- Enforce one terminal Agent response for every accepted user turn. Completion, no-op/idempotent execution, read-only answers, confirmation gates, failures, cancellation, timeout, and server-restart recovery must all append exactly one nonempty assistant bubble with the matching provenance badge. Persist a reply marker so refresh and repeated recovery never duplicate the terminal response.
- While a global local-Agent job is running, show `⏸ 停止` beside the disabled send action. Clicking it must persist a `cancelled` job plus one `已停止` assistant bubble, terminate the entire Codex process group, stop polling, re-enable input/send, and discard any late worker completion. Hide the stop action whenever no job is running.
- Make multi-turn structure visually unambiguous. Group each user message and following Agent response into a numbered round, separate rounds with a divider and spacing, show explicit `你`/`本地 Agent` labels plus distinct avatars, and use right-aligned teal user bubbles versus left-aligned purple Agent bubbles. Preserve multiline content and scroll to the newest round.

## Browser and state regression checks

- Keep the initial HTML shell non-interactive until the first `/api/state` response is rendered: hide both workspaces and the Agent launcher, and disable model, reset, view-switch, and compile controls. A slow or failed initial state request must leave a readable loading/error shell without any null-state JavaScript exception; successful project or empty-shell render explicitly enables only its valid controls.
- Dispatch every mutation control twice in the same JavaScript task against a delayed response and assert exactly one request. Cover Accept, mechanism Prompt/Image/build, Caption generation/save/approval, panel generation/composition, table generation/edit/save/approval, placement changes, and Agent chat send/cancel. A foreground request must lock all conflicting controls synchronously and restore them on success or failure; an already-running background job remains cancellable through its dedicated stop control.
- Treat `generation_ready: false` as a hard gate for both visible controls and automatic timers. Opening a blocked mechanism or data figure tab must remain request-free after the auto-generation delay; recheck the gate inside the timer callback because state may change after scheduling.
- Never treat an iframe `load` event as proof that a figure PDF exists: HTTP error pages also load. Before revealing data-figure confirmation, require a successful same-origin fetch whose first five bytes are `%PDF-`; use iframe load only to trigger or retry that verification. Bind the confirmation button's disabled state to the exact verified preview URL as well as hiding its container. A 404, HTML response, or stale URL must remain both hidden and non-invocable.
- Treat browser-cancelled SVG/PDF/static responses as normal transport teardown. Catch `BrokenPipeError` and `ConnectionResetError` at the response-body write boundary, close that connection, and do not emit handler tracebacks that obscure genuine server failures.
- Capture section, paragraph, artifact, and visible field values before every asynchronous request. If the researcher navigates while it is running, apply the response only to that captured target; never write a late F1 candidate into F3, clear another artifact's draft, or approve the newly selected artifact. For competing read-only navigation such as PDF reverse lookup, use latest-request-wins. Show mutation failures in the currently visible workbench rather than a hidden view's message element.
- Disable every input whose value is captured by an in-flight foreground mutation until that request succeeds or fails. This includes prose/correction/model fields during Generate/Accept, title and Title GPT Prompt during title requests, mechanism/data/table workbench inputs during their artifact request, and blocked data-panel generation buttons. Do not let late foreground responses overwrite text typed after submission. Keep the rest of the application responsive for genuine background Agent jobs.
- Entering the Figure or Table tab from a section with no matching artifact must switch to the first configured artifact's source section and show its cards/detail. Figure public records use concrete kinds such as `mechanism` and `data`; never look for a nonexistent generic `kind == figure` when choosing this fallback.
- Default new and empty Studio states to `gpt-5-nano` for text GPT API calls. Keep the browser field, frontend fallback, and server fallback identical; preserve a persisted project model and the explicit `PAPER_STUDIO_MODEL` environment override.
- Paper Studio is a permanent empty-capable application, not an output of `/paperwrite`. `python3 -m paper_studio.server --empty` must start without `paper/` or project config, render a clear empty state, expose no stale manuscript/PDF, and require no API key. When `paper/paper_studio.json` appears, restart the same fixed engine normally to load it; never generate per-paper HTML, JavaScript, CSS, or server code.
- Treat `paper_studio/` as one fixed application and `paper/paper_studio.json` as the per-paper configuration boundary. Never require regenerated HTML/JavaScript/Python application code merely because the paper changes. A different `project.id` must start fresh runtime state; same-project config edits must preserve it.

Persist monotonic per-artifact job revisions and merge only the newer artifact state so an unrelated stale whole-state save cannot turn a completed draft back into `image_generating`. On restart, recover a completed image only when its archived prompt exactly matches the current approved prompt; otherwise mark the interrupted job failed with a retry action.
